核心概念词典

读懂这些词，能让你和研究员、技术同事沟通时无障碍。

假设 Hypothesis
一段自然语言的经济学逻辑，例如"20 日反转在 A 股截面回补"。它是因子被创造出来的"理由"，用来事后追溯因子来源。
DSL 因子 Domain-Specific Language Factor
在受限算子集（截面排名、时序移动平均、变化率、延迟、缩尾等 8 个安全函数 + 四则运算）下能解析执行的因子表达式，不允许任意代码，以保证远程执行安全。
RankIC Rank Information Coefficient
因子排序与未来 5 日收益排序的日频斯皮尔曼相关系数的均值。衡量"排序预测力"的核心指标，门控的主指标。
ICIR IC Information Ratio
RankIC 的均值除以它的波动率，反映"预测力是否稳定"。一个 ICIR 高的因子比一个 IC 高但波动也大的因子更值得用。
公告日口径 Point-in-Time Discipline
财务字段以"公告日 dt"而非"会计期间 report"对市场可见。杜绝"年报数字在公告之前就被使用"这种回测偏差。
多空价差 Long-Short Spread
每日按因子排序买入头部 20%、卖空尾部 20% 得到的日均收益差。是因子收益贡献的直接度量。
接受门槛 V1 Gate
硬性指标红线——RankIC 绝对值 ≥ 0.03、年化收益 ≥ 0、Sharpe ≥ 0.30、最大回撤 ≤ 0.35、换手率 ≤ 1.0、覆盖率 ≥ 0.50。
去重阈值 Dedup Threshold 0.88
与已通过因子的 Pearson、Spearman 或收益序列相关性的绝对值超过 0.88 即视为重复。避免因子库被"换皮版本"塞满。
02 · END-TO-END PIPELINE

一条因子从无到有的全链路

整条链路是"本地 AI 推理 → 远端数据机执行 → 本地多指标把关 → 登记"的循环闭环。下面是 11 个业务环节的可视化总览，点击下方任意步骤可定位详情。

STEP 01
研究循环启动
本地发起启动命令，装配 LLM 后端（DeepSeek），加载场景配置：评估窗口 2022-01-01 至 2023-12-31、远端数据根目录、SSH 凭据等。
本地
STEP 02
DeepSeek 假设生成
把上一轮"全量指标 + 失败原因"回灌给 LLM，让它在价量或基本面方向上提出 1–3 个新假设，含假设文字 + 字段白名单 + 表达式三件套。
LLM
STEP 03
假设 → 因子任务编排
为每条假设生成因子子任务，指定名字、所属家族（价量/基本面）、DSL 表达式、研究假设文本。家族可由表达式自动推断。
本地
STEP 04
DSL 语法校验
解析表达式的抽象语法树，强制只允许四则运算和 8 个白名单函数，只允许白名单字段。关键字参数、布尔值、字符串一律拒绝。
本地
STEP 05
评估请求打包 + SSH 传输
构造只含数据的 JSON 请求体，连同远端 worker 脚本一起投到数据机工作目录。凭据始终留在本地，绝不外发；远端路径强制白名单字符。
远端
STEP 06
远端因子值计算
worker 仅按表达式实际用到的字段去 G:/base 取数（价量宽表直读、财务按"公告日 → 前向填充"做点分时），按 8 个函数做截面/时序运算，产出每日 × 全 A 因子面板。
远端
STEP 07
13 项指标计算
IC 系列、收益/风险系列、换手/覆盖、按年稳定性。T 日因子在 T+1 开盘生效，杜绝同日偷价；每 5 日采样、最小截面 100 只。
远端
STEP 08
6 项硬门槛筛选
逐条对照 RankIC、年化收益、Sharpe、最大回撤、换手率、覆盖率。一项不满足即拒绝，并记下失败项供下一轮 LLM 改进。
本地
STEP 09
4 道去重
与库里所有"已登记"因子比较：表达式归一哈希、因子值 Pearson、因子值 Spearman、多空收益序列相关。任何一项 ≥ 0.88 即判重复。
本地
STEP 10
SQLite 登记
对每个候选做"存在则更新、不存在则插入"，统一写入因子表。因子 ID 由"名称 + 表达式"哈希生成，保证重跑幂等。
登记
STEP 11
反馈 + 下一轮
把本轮全量指标按"当期值 / 历史基准 / 增量"三栏渲染成自然语言反馈，再由 LLM 决定是否替换当前最佳基线，进入下一轮。
LLM
03 · ACCEPTANCE GATE

6 项硬门槛，缺一不可

一个候选因子要被登记为"已接受"，必须同时通过下列 6 个硬指标。任意一项不达标即被标记为"rejected"并写入登记表留档。

硬门槛
排名信息系数
|RankIC| ≥ 0.03
因子排序与未来 5 日收益排序的日频相关系数均值，衡量排序预测力
硬门槛
年化超额收益
≥ 0
多空对冲组合的年化收益不为负；负贡献因子直接拒
硬门槛
信息比 / 夏普
≥ 0.30
单位波动下年化超额至少 0.30，风险调整后勉强可用
硬门槛
最大回撤（绝对值）
≤ 0.35
极端不利情形损失不超过 35%，避免被定性为高风险
硬门槛
换手率
≤ 1.0
日均组合调整不超过 100%，过滤高频微动导致的高成本
硬门槛
截面覆盖率
≥ 0.50

04 · DE-DUPLICATION

4 道去重关卡，杜绝"换皮版本"

通过硬门槛的因子，还要和库里所有"已接受"因子做 4 层比较，任一命中即判重复。判重不丢记录——会以 duplicate 状态入库并挂上"撞车对象"的引用。

关卡 1
表达式归一化匹配
把表达式解析为抽象语法树后再归一化求 SHA-256 哈希。a + b 与 a+b 视作完全等价；带多余空格、写法变体都算同一表达式。
100%精确 命中即重复
关卡 2
因子值 Pearson 相关
逐个与已接受因子做因子值序列的 Pearson 相关系数，要求至少 100 个共同有效观测日。绝对值 ≥ 阈值即重复。
≥ 0.88 阈值 / 最小重叠 100 日
关卡 3
因子值 Spearman 相关
同上，但用秩相关，对极端值更稳健。线性变换差异不影响判定，捕捉"换函数但信号一致"的改写。
≥ 0.88 阈值 / 最小重叠 100 日
关卡 4
多空收益序列相关
即使因子本身不直接相关，但"用它们构建的多空组合"日收益高度相关也算重复——这是更接近"投研等价"的判重标准。
≥ 0.88 阈值 / 最小重叠 100 日
业务含义："去重"服务于下游交付的"信号多样性"。 同样的信号拿 5 个变体入册，等于把组合暴露在同一个风险因子上；4 道去重让因子库代表不同的收益来源。
05 · DATA PIPELINE

从假设到登记，产物如何在两台机器间流转？

"本地"是研究控制端（用 Mac/PC 即可），"远端"是数据机（合规要求数据不出域）。所有数据搬运都遵循"只传必要数据、不传任何凭据"的原则。

🔒 凭据留在本地

SSH 密码/Token 永远只存在控制端进程的内存里，从未跨边界传输。远端 worker 启动时只用请求/结果两个文件路径作为命令行参数。

📦 重因子值、轻请求

上行是"小 JSON"（只含数据），下行是"大 Parquet"（每日 × 全 A 因子值）。两台机器按各自的能力分工：远端管数据，本地管决策。

🧬 因子 ID 幂等

每条记录的唯一 ID 由"名称 + 表达式"的密码学哈希决定。同样的输入多次提交只会更新同一条记录——重跑、补跑都不会污染库。

📅 公告日防穿越

财务字段以"公告日 dt"为可用起点，沿交易日逐日前向填充。杜绝"年报数字在公告之前就被使用"这种典型回测偏差。

06 · FAULT HANDLING

出了错怎么办？

系统对"失败"有清晰的态度：单点失败不拖垮整轮；远端故障不会"静默降级"为本地宽表；所有失败都会以可追溯的形式留档。下面是 7 类典型异常与对应处置。

异常情形 系统行为 业务后果 处置方式
远端数据机不可达 不静默回退 本轮该候选记为运行失败 记入失败样本清单；其余候选继续；整轮失败则跳过本轮
DeepSeek 假设生成失败 反馈回提示 单点假设失败不拖死整条研究线 把"无可解析候选"作为反馈写回下一轮，每族最多 5 轮
因子代码运行报错 逐候选隔离 失败的那一条不拖累同轮兄弟候选 失败原因回喂给 LLM，避免下轮重提相同表达
指标缺失或不达标 NaN 视同失败 不合格因子"留痕不留名" 原始指标向量、产物路径、失败原因全部入库备查
重复登记 幂等更新 同表达式多次提交只更新同一条 研究循环天然具备幂等性，重跑/补跑不污染库
SSH 主机指纹不匹配 硬校验拒绝 杜绝静默中间人攻击 需要运维主动更新配置才会放行，是"宁断不断"的策略
回写反馈 全指标回灌 LLM 不只看通过/未通过的二值结论 13 项核心指标 + 按年稳定性，全量反馈给 LLM

一次研究循环的真实时间线

以"20 日反转因子"为例，看一条因子从假设提出到最终落库的全过程。注意 LLM 调用的耗时、远端评估的耗时，以及每一步之间的反馈环。

T+0s

DeepSeek 假设生成

LLM · ~10s
① -pct_change(adjclose, 20) — 20 日反转（价量族）
② ts_mean(volume, 5) / ts_std(close, 20) — 量价背离（价量族）
③ -signed_log(pb) — 价值反转（基本面族）

{

    "end": "2023-12-31",
    "label_horizon": 5,
    "quantile": 0.2,
    "min_cross_section": 100,
    "sample_step": 5
  }
}

-pct_change(adjclose, 20)
STEP B · 评估结果（典型一次）
13 项指标快照
RankIC = 0.045 ✓  |  年化 = 8.2% ✓  |  Sharpe = 0.45 ✓
回撤 = -22% ✓  |  换手 = 0.8 ✓  |  覆盖 = 0.78 ✓

4 道去重关卡

STEP D · 落库状态
SQLite 记录
status = duplicate · dedup_of = 已接受因子 ID · metrics 全量留档 · 失败原因 / 撞车对象全部 JSON 化保存。
09 · SCOPE & LIMITS

它能做什么、不能做什么？

清晰认识边界比夸大能力更重要。下面的对照表帮助产品/业务方在引入前对"适用场景"和"不适用场景"形成准确预期。

✅ 适用的场景

  • 可由行情和财报计算的传统横截面因子（量价、动量、反转、波动率、估值、成长性等）
  • 需要批量生成原型、快速扩充因子库的"广撒网"阶段
  • 研究员数量有限、希望把重复劳动自动化的研究团队
  • 希望把研究过程结构化、可追溯、可复算的合规与审计场景
  • 需要历史回放、跨期比较的因子库治理

❌ 不适用的场景

  • 非线性组合因子（依赖机器学习集成、复杂优化）
  • 另类数据因子（舆情、卫星、文本情感等结构外数据）
  • 日内高频因子（当前 DSL 算子仅支持日频或更低频运算）
  • 事件驱动因子（依赖新闻、公告、突发事件的实时信号）
  • 对生产收益直接负责的策略层（智能体只产信号，不做组合）

把这一切装进一句话

广发 A 股因子智能体是一台"研究流水线"——DeepSeek 当研究员不停出假设，远端数据机当回测引擎贴着 G:/base 算因子，本地控制器用 6 项硬门槛 + 4 道去重把不合格的过滤掉， 合格的沉淀进 SQLite 因子登记册。每轮的全量指标再回灌给 DeepSeek，让它在下轮针对具体短板改进。

  • 上游：广发自有 A 股数据 + DeepSeek 大模型 + 远程数据机 SSH 通道
  • 中游：假设 → 远端评估 → 门槛 → 去重 → 登记的 11 步业务闭环
  • 下游：已登记因子库（SQLite 元数据 + 远端 Parquet 因子值）
