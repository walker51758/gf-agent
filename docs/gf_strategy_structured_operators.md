# GF 策略智能体：结构化组合算子扩展目录

> 文档性质：设计草案与评审记录，不代表所有算子已经在当前代码中实现。
> 当前生产状态仍是归零状态：活动因子 registry 与策略 registry 均为空。
>
> 固定执行事实：买入 10 bps、卖出 10 bps、完整往返 20 bps。交易成本不是
> 策略算子参数，不能出现在 LLM 输出、`StrategyCandidate`、CLI、环境变量或
> settings 中。任何新增算子都必须保持声明式、确定性、可审计，不能让模型生成
> Python 或回测代码。

## 1. 当前已经能表达什么

当前实现可以把一个策略表达为以下数据流：

```text
冻结 working set 中的 2–8 个因子
        ↓
按各因子既定方向做横截面百分位排名
        ↓
等权平均为综合分
        ↓
每个调仓日选择 Top-N
        ↓
等权 / 名次权重 / 正分数比例配权
        ↓
可选单票权重上限，剩余部分留现金
        ↓
至少 1 日信号滞后、持仓漂移、固定买卖成本
        ↓
组合回测、验收、去重、registry 与报告
```

其中 `rule` 当前主要是审计说明文字，不会自动解释成任意交易逻辑。因此，下面
新增的算子要先落成受限 schema，再由确定性执行器实现，不能仅把名称塞进 `rule`。

## 2. 算子统一契约

每个算子建议使用统一结构：

```json
{
  "name": "operator_name",
  "version": 1,
  "category": "universe|signal|selection|constraint|weight|execution|risk|audit",
  "input": "上游数据对象或中间结果",
  "output": "下游数据对象",
  "parameters": {},
  "parameter_ownership": "agent|system|calibration",
  "data_requirements": [],
  "availability_lag": "T-1 or explicit PIT rule",
  "deterministic": true,
  "failure_policy": "reject|cash|fallback|warn",
  "audit_fields": []
}
```

参数所有权必须明确：

| 所有权 | 含义 |
|---|---|
| `agent` | 策略智能体可以在允许范围内声明，仍须 schema 校验和 OOS 审计 |
| `system` | 系统固定事实，智能体不可修改，例如买卖成本、信号滞后下限、PIT 规则、硬交易约束 |
| `calibration` | 由研究流程或人工标准确定，不由单次 LLM 提案自由设置；修改需产生新版本 |

所有算子还必须记录：输入快照 ID、参数 canonical JSON、schema 版本、输出 checksum、
数据截止日、缺失/降级数量以及失败原因。

## 3. 候选池与可交易性算子

这些算子先决定“哪些股票允许进入后续计算”。过滤结果应是 `eligible[t, symbol]`
布尔面板；不可交易股票必须在权重生成前被排除，而不是事后从订单中删除。

### 3.1 `BaseUniverse`

- 输入：全市场证券主表、策略声明的 universe。
- 输出：初始股票集合。
- 参数：市场（A 股）、交易所、指数或自定义 universe ID。
- 数据：证券主表、历史成分表。
- 当前状态：已有 `universe` 字符串，但还没有完整的历史成员执行器。
- 风险：静态当前成分回填历史会产生生存者偏差；必须使用 PIT 成分。

### 3.2 `IndexMembershipFilter`

- 输入：`BaseUniverse`、历史指数成分和生效日期。
- 输出：按信号日生效的指数成分子集。
- 参数：指数代码列表、生效滞后、是否剔除刚纳入成分。
- 数据：指数历史成分、调样公告和生效日。
- 当前状态：路线图。
- 风险：使用公告日而非生效日、或提前使用调样结果，会前视。

### 3.3 `ListingAgeFilter`

- 输入：候选股票和上市日期。
- 输出：上市满 N 个交易日的股票。
- 参数：`min_listing_days`。
- 数据：上市/退市日期、交易日历。
- 建议默认：60 或 120 个交易日，具体值属于 calibration，不是硬编码真理。
- 风险：新股收益分布与老股不同；过滤过严会缩小股票池。

### 3.4 `StatusExclusionFilter`

- 输入：候选股票、ST/*ST、退市整理、风险警示、停牌状态。
- 输出：状态合格股票。
- 参数：排除列表；ST 历史状态是否按当日状态处理。
- 数据：逐日证券状态主表。
- 当前状态：路线图。
- 风险：用当前 ST 状态回填历史；停牌状态必须按交易日保存。

### 3.5 `PriceLimitTradabilityFilter`

- 输入：候选股票、涨跌停价、信号日可交易状态。
- 输出：当日可买/可卖掩码，而不仅是单个 eligible 布尔值。
- 参数：是否排除一字涨停、是否允许持有但不买入、涨跌停判定口径。
- 数据：原始价格、涨跌停规则、停牌和交易状态。
- 当前状态：路线图。
- 风险：科创板、创业板、ST 的涨跌停比例不同；复权价不能直接用于交易可行性判断。

### 3.6 `LiquidityFilter`

- 输入：候选股票和历史成交量/成交额。
- 输出：流动性合格集合。
- 参数：20/60 日平均成交额下限、分位数下限、缺失处理。
- 数据：日成交额、成交量、自由流通市值。
- 当前状态：路线图。
- 风险：使用信号日之后的数据；极端成交日抬高均值；不同市值层不能直接共用绝对阈值。

### 3.7 `PriceRangeFilter`

- 输入：候选股票价格序列。
- 输出：价格在允许区间内的集合。
- 参数：最低价格、最高价格、连续交易天数。
- 数据：原始收盘价、交易状态。
- 当前状态：路线图。
- 风险：低价股过滤可能混入拆股/复权口径错误；价格过滤不是流动性过滤的替代品。

### 3.8 `DataQualityFilter`

- 输入：因子面板、行情面板、主数据。
- 输出：数据质量合格掩码及质量诊断。
- 参数：最小覆盖率、最大缺失连续长度、异常值规则、价格非正规则。
- 数据：所有上游面板及其 provenance。
- 当前状态：部分由因子/worker 校验，组合层需统一化。
- 风险：把“缺失”错误填成 0 会改变排序；质量降级必须进入报告。

## 4. 因子与信号变换算子

这些算子作用于因子值，不直接下订单。所有横截面变换必须在信号日使用可获得数据，
并记录分母、有效样本数和方向。

### 4.1 `DirectionMap`

- 输入：因子值和因子方向。
- 输出：统一为“越大越好”的值。
- 参数：每个因子 `+1/-1`。
- 数据：因子 registry 的冻结方向。
- 当前状态：已执行。
- 风险：智能体不能自行改变 registry 中的方向；方向变化应生成新因子版本。

### 4.2 `CrossSectionalRank`

- 输入：当日因子横截面。
- 输出：百分位或序数排名。
- 参数：排名方法、是否按行业内排名、最小样本数。
- 数据：因子面板、eligible 掩码。
- 当前状态：已执行百分位排名。
- 风险：并列值处理不一致会导致边界股票漂移；行业内排名属于新语义，不应暗中启用。

### 4.3 `Winsorize`

- 输入：横截面因子值。
- 输出：截尾后的因子值。
- 参数：上下分位点、MAD 或分位数方法、最小样本数。
- 数据：因子值。
- 当前状态：路线图。
- 风险：每期动态估计边界会放大样本噪声；边界必须只由当期可用横截面计算并记录。

### 4.4 `CrossSectionalStandardize`

- 输入：因子值或截尾值。
- 输出：z-score、rank-z 或 robust z-score。
- 参数：标准化方法、最小标准差、是否使用中位数/MAD。
- 数据：因子横截面。
- 当前状态：路线图。
- 风险：横截面极端值；标准差接近零时必须拒绝或降级，而不是产生无穷值。

### 4.5 `MissingValuePolicy`

- 输入：多个因子面板。
- 输出：补齐或剔除后的面板及缺失标记。
- 参数：`drop_stock`、`fill_cross_section_median`、`fill_neutral_rank`、最大填充比例。
- 数据：因子面板。
- 当前状态：当前逻辑倾向于无效股票不参与排名；需显式 schema 化。
- 风险：中性填充与真实中性不是一回事；必须报告每期填充数量。

### 4.6 `IndustryNeutralize`

- 输入：因子值、行业标签，可选市值/风格暴露。
- 输出：行业内去均值或回归残差。
- 参数：行业分类版本、回归/分组方法、最小组样本数、是否加权。
- 数据：PIT 行业分类、风格字段。
- 当前状态：路线图。
- 风险：行业分类版本变更；样本少的行业需要明确 fallback；中性化可能删除真实行业 alpha。

### 4.7 `StyleNeutralize`

- 输入：因子值、规模、beta、动量等风格暴露。
- 输出：风格中性因子值或残差。
- 参数：风格字段、回归窗口、加权方式、最小样本数。
- 数据：PIT 风格暴露、基准或风险模型。
- 当前状态：路线图。
- 风险：短窗口估计不稳定；风格字段本身若使用未来数据会污染因子。

### 4.8 `FactorTransform`

- 输入：因子值。
- 输出：单调变换后的因子值。
- 参数：线性、log、signed-log、rank、平方根；变换适用域。
- 数据：因子面板。
- 当前状态：路线图。
- 风险：log 对非正值必须 fail-closed；变换不可作为任意代码入口。

### 4.9 `FactorBlend`

- 输入：2–8 个对齐后的因子得分。
- 输出：综合分及逐因子贡献。
- 参数：等权、预先冻结的固定权重、分组权重；权重是否归一化。
- 数据：因子面板、方向、质量统计。
- 当前状态：已支持等权平均；固定权重需新增 schema。
- 风险：IC 加权若每期重估会前视和过拟合；权重必须有冻结窗口和 OOS 规则。

### 4.10 `FactorGroupBlend`

- 输入：按价值/质量/成长/风险/价量等分组的因子。
- 输出：先组内合成、再组间合成的综合分。
- 参数：组定义、组内权重、组间权重、缺失组处理。
- 数据：因子 registry 的 family/theme/intended_role。
- 当前状态：路线图。
- 风险：组划分改变会导致策略 identity 改变；组权重不是“免费参数”。

### 4.11 `FactorInteraction`

- 输入：两个或多个标准化因子。
- 输出：交互分数，例如质量高且价值低估的联合信号。
- 参数：乘积、min、geometric mean、门控交互；是否先 rank。
- 数据：对齐因子面板。
- 当前状态：路线图。
- 风险：乘积放大噪声；交互算子数量必须受限并做消融审计。

### 4.12 `RegimeConditionalSignal`

- 输入：主因子信号、预先定义的市场状态。
- 输出：状态条件下的信号或权重。
- 参数：状态字段、状态阈值、每个状态的因子组合、状态切换滞后。
- 数据：只使用 PIT 可得的指数收益、波动、利率或宏观状态。
- 当前状态：路线图。
- 风险：状态定义容易隐含未来；切换过于频繁会显著增加换手。

## 5. 选择与排序算子

### 5.1 `QuantileGate`

- 输入：因子或综合分横截面。
- 输出：通过某一分位阈值的集合。
- 参数：分位点、方向、最小通过数、空集处理。
- 当前状态：路线图。
- 风险：分位点叠加过多会导致候选池过窄。

### 5.2 `CascadedFactorGating`

- 输入：股票池和多个因子。
- 输出：按顺序经过多层门控的集合。
- 参数：门控顺序、每层因子、阈值、`and/or`、最终 Top-K。
- 当前状态：路线图。
- 风险：顺序会产生隐含优先级；必须做顺序敏感性和候选数量审计。

### 5.3 `TopKSelector`

- 输入：综合分或排序分。
- 输出：Top-K 股票集合。
- 参数：K、并列处理、最小有效样本数。
- 当前状态：已支持 Top-N。
- 风险：K 超过有效股票数时要明确是全选还是拒绝；并列需稳定按 symbol 打破。

### 5.4 `RankTieBreaker`

- 输入：有并列分数的排序结果。
- 输出：稳定排序。
- 参数：symbol、流动性、前期持仓优先级；优先级必须固定。
- 当前状态：当前执行器使用确定性 symbol tie-break。
- 风险：使用当日收盘后才知道的字段会引入时序问题。

### 5.5 `HoldingBuffer`

- 输入：当前持仓、旧排名、新排名。
- 输出：带缓冲区的进出场集合。
- 参数：入选阈值、保留阈值、最大额外持仓数。
- 数据：上一期持仓、当期排名。
- 当前状态：路线图。
- 风险：缓冲区降低换手但可能保留已失效股票；必须报告实际偏离。

### 5.6 `DiversitySelector`

- 输入：排序后的候选、行业/相关性标签。
- 输出：满足多样性约束的候选集合。
- 参数：最大相关性、每个行业最少/最多数量、贪心或确定性优化方法。
- 数据：行业标签、历史收益相关性。
- 当前状态：路线图。
- 风险：相关性窗口选择会影响结果；贪心算法需固定 tie-break 并报告未选原因。

## 6. 行业、风格与组合约束算子

这些算子作用在目标权重上，输出新的可行权重和约束残差。它们不应默默改变
因子分数；若重分配导致信号偏离，要同时输出偏离指标。

### 6.1 `SingleNameCap`

- 输入：初始权重。
- 输出：单票上限后的权重。
- 参数：上限、剩余资金处理。
- 当前状态：已支持确定性 water-filling。
- 风险：`K × cap < 1` 时必须保留现金，不能强行超限。

### 6.2 `SingleNameFloor`

- 输入：候选权重。
- 输出：带最小有效头寸的权重。
- 参数：最小权重、最小交易金额、是否允许现金残差。
- 当前状态：路线图。
- 风险：小权重会增加订单数量和摩擦成本；不能与单票上限冲突。

### 6.3 `IndustryWeightCap`

- 输入：个股权重和行业标签。
- 输出：单行业权重上限后的权重。
- 参数：行业分类版本、每行业上限、超额再分配规则。
- 当前状态：路线图。
- 风险：行业分类变化、再分配循环和现金残差必须可重现。

### 6.4 `IndustryDeviationConstraint`

- 输入：组合行业权重、基准行业权重。
- 输出：行业主动偏离受限的权重。
- 参数：每行业最大绝对偏离、是否允许行业豁免。
- 数据：PIT 基准权重、行业映射。
- 当前状态：路线图。
- 风险：基准成分和行业权重必须按信号日可得信息冻结。

### 6.5 `StyleExposureConstraint`

- 输入：权重、风格暴露矩阵、基准暴露。
- 输出：风格暴露在区间内的权重。
- 参数：风格列表、主动暴露上下限、约束优先级。
- 数据：风险模型风格暴露、基准。
- 当前状态：路线图。
- 风险：风险模型版本漂移会破坏复现；硬约束和软告警必须分开。

### 6.6 `BetaConstraint`

- 输入：权重、个股 beta、基准 beta。
- 输出：beta 区间内的权重。
- 参数：beta 上下限或主动 beta 上限。
- 数据：PIT beta 估计。
- 当前状态：路线图。
- 风险：beta 窗口与行业暴露共线，优化可能无解；需要降级策略。

### 6.7 `FactorExposureConstraint`

- 输入：权重、风险因子暴露矩阵。
- 输出：目标因子暴露范围内的权重。
- 参数：暴露上下限、优先级、软约束惩罚系数。
- 数据：风险模型或冻结的风格/主题暴露。
- 当前状态：路线图。
- 风险：把 alpha 因子同时当作硬风险因子可能过度中性化。

### 6.8 `CashResidualPolicy`

- 输入：约束后权重及未分配资金。
- 输出：最终股票权重与现金权重。
- 参数：允许现金上限、残差保留、再分配顺序。
- 当前状态：当前单票上限不足以满仓时保留现金；需独立记录。
- 风险：现金收益、现金基准和资金占用口径必须固定。

### 6.9 `ConstrainedWeightProjection`

- 输入：初始目标权重和全部线性约束。
- 输出：距离初始权重最近的可行权重。
- 参数：距离函数、约束优先级、最大迭代数、无解处理。
- 数据：行业/风格/单票/现金约束数据。
- 当前状态：路线图。
- 风险：优化器非确定性、求解器版本和无解降级必须锁定；禁止让 LLM 传入目标函数代码。

## 7. 权重生成算子

### 7.1 `EqualWeight`

- 输入：选中股票集合。
- 输出：等权目标。
- 当前状态：已支持。

### 7.2 `RankWeight`

- 输入：有序股票集合。
- 输出：随排名递减的权重。
- 参数：线性或预定义 rank 曲线。
- 当前状态：已支持线性名次权重。
- 风险：排名权重集中度高于等权，需和单票上限联动。

### 7.3 `ScoreProportionalWeight`

- 输入：正分数股票集合。
- 输出：按正分数比例配权。
- 当前状态：已支持。
- 风险：极端分数敏感；负分数必须拒绝，不能隐式做空。

### 7.4 `ScoreTransformWeight`

- 输入：综合分。
- 输出：经过线性、截断或预定义 sigmoid 变换的权重。
- 参数：变换类型、斜率、截断点。
- 当前状态：路线图。
- 风险：变换参数易过拟合；必须记录完整曲线参数。

### 7.5 `InverseVolatilityWeight`

- 输入：选中股票和历史波动率。
- 输出：逆波动权重。
- 参数：波动窗口、最小波动率、是否与综合分相乘。
- 数据：PIT 收益序列。
- 当前状态：路线图。
- 风险：低波动估计会获得过大权重；估计窗口必须不跨越信号日之后。

### 7.6 `RiskParityWeight`

- 输入：选中股票、协方差/风险模型。
- 输出：风险贡献近似相等的权重。
- 参数：风险预算、协方差收缩方法、迭代容差。
- 数据：PIT 协方差或风险模型。
- 当前状态：路线图。
- 风险：协方差估计误差、求解器不可复现和极端权重。

### 7.7 `FactorRiskBudgetWeight`

- 输入：个股因子暴露、目标因子预算。
- 输出：按因子风险预算的权重。
- 参数：因子预算、特异风险上限、正则化。
- 数据：风险模型、个股暴露。
- 当前状态：路线图。
- 风险：需要把 alpha 贡献和风险暴露区分开，否则解释会循环论证。

### 7.8 `HierarchicalWeighting`

- 输入：行业/因子组层级和候选股票。
- 输出：先分配组权重、再分配组内权重的结果。
- 参数：组间权重、组内规则、空组 fallback。
- 当前状态：路线图。
- 风险：层级顺序本身是策略假设，需要单独做消融。

## 8. 调仓与交易可行性算子

### 8.1 `RebalanceSchedule`

- 输入：目标权重面板、交易日历。
- 输出：实际信号日和调仓日。
- 参数：日/周/月/季、月内第 N 个交易日、节假日规则。
- 当前状态：已支持 daily/weekly/monthly/quarterly 的基础选择。
- 风险：调仓日必须使用历史交易日历；不能用自然日简单切片。

### 8.2 `SignalLag`

- 输入：信号日目标权重。
- 输出：可交易日目标权重。
- 参数：滞后天数，系统下限为 1。
- 当前状态：已支持。
- 风险：0 日滞后造成 look-ahead，必须 fail-closed。

### 8.3 `DriftBandRebalance`

- 输入：当前漂移权重、目标权重。
- 输出：仅在偏离超过带宽时触发的调仓。
- 参数：单票带宽、组合带宽、强制定期重平衡。
- 当前状态：路线图。
- 风险：带宽过宽会让组合长期偏离，过窄会放大换手。

### 8.4 `MinimumHoldingPeriod`

- 输入：当前持仓、入场日期、退出信号。
- 输出：满足最低持有期后的订单集合。
- 参数：最少持有交易日、强制退出例外。
- 当前状态：路线图。
- 风险：会延迟负面信号；停牌、退市等系统风险必须优先于该算子。

### 8.5 `TurnoverShrinkage`

- 输入：旧权重与目标权重。
- 输出：向目标收缩后的权重。
- 参数：最大单次换手、hard clip 或 soft shrink、收缩比例。
- 当前状态：路线图。
- 风险：不能把回测中的换手限制当成事后优化目标；实际偏离必须记录。

### 8.6 `ParticipationCap`

- 输入：订单金额、历史成交量/成交额。
- 输出：分日拆分的订单。
- 参数：最大成交参与率、订单最大期限、未成交处理。
- 数据：成交量、成交额、盘口或冻结冲击模型。
- 当前状态：路线图。
- 风险：成交量预测不可使用未来值；未成交部分不能神秘地补成交。

### 8.7 `LotRounding`

- 输入：目标金额、价格、最小交易单位。
- 输出：可下单股数及现金残差。
- 参数：沪深整手规则、最小订单金额、舍入方向。
- 数据：原始价格、交易所规则。
- 当前状态：路线图。
- 风险：取整后权重偏离可能不小；必须保留订单和残差审计。

### 8.8 `SideAwareTradability`

- 输入：买卖订单、停牌/涨跌停/借券状态。
- 输出：可买订单、可卖订单、未成交订单。
- 参数：买卖分别的拒单规则、是否允许持仓但不可买入。
- 当前状态：路线图。
- 风险：买卖可行性不能压缩成一个对称布尔值。

### 8.9 `StagedExecution`

- 输入：大额目标换手、参与率上限。
- 输出：多个交易日的确定性订单计划。
- 参数：最大执行天数、每天参与率、优先级顺序。
- 当前状态：路线图。
- 风险：跨日执行会改变暴露；必须把订单计划纳入回测，而不是只调整最终收益。

### 8.10 `FixedExecutionCost`

- 输入：实际买入额和卖出额。
- 输出：净收益和成本审计。
- 参数：无 agent 参数。系统固定买入 10 bps、卖出 10 bps。
- 当前状态：已实现。
- 风险：任何 cost 字段进入 candidate 或 request 的旧 payload 都必须忽略或拒绝；不能由模型报价。

## 9. 风险控制算子

风险算子建议分为硬约束、软告警和监控三类。不能让策略智能体把“熔断”当成任意
动态交易脚本；每个动作必须是有限状态机中的明确转移。

### 9.1 `PortfolioVolatilityTarget`

- 输入：组合历史收益或风险模型。
- 输出：组合总仓位缩放因子。
- 参数：目标年化波动率、估计窗口、缩放上下限。
- 当前状态：路线图。
- 风险：波动率跳升时会产生追涨杀跌；要区分风险缩放和选股信号。

### 9.2 `DrawdownStateMachine`

- 输入：净值、高水位、回撤。
- 输出：正常/预警/减仓/暂停状态。
- 参数：阈值、确认天数、恢复条件、最大缩放比例。
- 当前状态：路线图。
- 风险：状态规则需冻结；恢复条件不能使用未来信息。

### 9.3 `StressScenarioCheck`

- 输入：组合权重、行业/风格暴露、历史压力情景。
- 输出：压力损失和是否通过。
- 参数：压力情景 ID、损失阈值、告警/硬拒绝。
- 数据：历史危机窗口、风险模型。
- 当前状态：路线图。
- 风险：情景选择会造成选择偏差；必须把完整情景表版本化。

### 9.4 `ConcentrationMonitor`

- 输入：个股、行业、主题权重。
- 输出：集中度指标与告警。
- 参数：HHI、Top-5/Top-10、单行业阈值。
- 当前状态：单票 cap 已有，综合集中度监控未完整实现。
- 风险：监控指标不能悄悄重写策略权重，除非明确声明为硬约束算子。

### 9.5 `FactorDecayMonitor`

- 输入：滚动 IC、ICIR、因子暴露、组合收益。
- 输出：有效性诊断和有限状态信号。
- 参数：窗口、连续失败期数、暂停/恢复规则。
- 当前状态：路线图。
- 风险：自动暂停会改变样本路径；必须单独做状态敏感性和 OOS 审计。

## 10. 评价、审计与治理算子

### 10.1 `WalkForwardEvaluation`

- 输入：冻结策略 schema、分段数据窗口。
- 输出：逐段 IS/OOS 指标。
- 参数：训练/验证/测试切分、滚动步长、最小 OOS 段数。
- 当前状态：已有 epoch 窗口和远端评价基础，完整 walk-forward 仍是路线图。
- 风险：反复查看 OOS 并据此改参数会把 OOS 变回 IS。

### 10.2 `CostSensitivityAudit`

- 输入：固定成本下的策略结果。
- 输出：成本扰动敏感性表。
- 参数：仅审计情景，例如 10/15/20 bps 买卖成本；不改变生产成本契约。
- 当前状态：路线图。
- 风险：敏感性情景不能被误写回策略配置，也不能替代真实冲击成本。

### 10.3 `ParameterPerturbationAudit`

- 输入：已冻结策略规格。
- 输出：Top-N、权重 cap、窗口等参数扰动结果。
- 参数：预先登记的扰动集合。
- 当前状态：路线图。
- 风险：扰动集合不能根据结果临时挑选；报告需区分事前和事后分析。

### 10.4 `AblationAudit`

- 输入：完整策略和逐算子/逐因子移除版本。
- 输出：边际收益、Sharpe、回撤、换手贡献。
- 参数：移除粒度、最小样本量。
- 当前状态：因子消融基础已存在，算子级消融待扩展。
- 风险：消融不是因果证明；结果应表述为 ex-post 描述。

### 10.5 `ReturnProfileDedup`

- 输入：日度净收益轨迹、已接受策略库。
- 输出：accepted/duplicate 及相似策略 ID。
- 参数：相关性阈值、最小重叠长度。
- 当前状态：已支持。
- 风险：不同窗口的 profile 不可直接比较；必须记录窗口和缺失处理。

### 10.6 `FeasibilityAudit`

- 输入：目标权重、订单计划、停牌/涨跌停、成交量。
- 输出：可执行比例、未成交金额、约束违反。
- 参数：最低可执行比例、是否允许现金残差。
- 当前状态：路线图。
- 风险：回测中“理论成交”与实际可成交必须分开报告。

### 10.7 `DataLeakageAudit`

- 输入：算子 DAG、字段可用时间、代码/规格版本。
- 输出：前视风险清单。
- 参数：字段 availability lag、公告日至生效日规则。
- 当前状态：分散在因子/策略校验中，需统一报告。
- 风险：仅检查代码字符串不够；必须检查数据时间语义。

### 10.8 `StrategyManifestEmitter`

- 输入：通过验收的完整算子 DAG。
- 输出：不可变 JSON manifest。
- 参数：schema 版本、算子版本、参数 checksum、因子 ID、成本事实、数据窗口。
- 当前状态：registry/report 已有部分 provenance，完整 manifest 待扩展。
- 风险：schema 演进要兼容读取；任何参数改动必须产生新 identity。

### 10.9 `ReproducibilityCheck`

- 输入：manifest、snapshot、artifact checksum、worker 版本。
- 输出：可复跑/不可复跑判定。
- 参数：允许的浮点误差、结果 checksum 规则。
- 当前状态：已有 snapshot、artifact 和 request checksum 基础。
- 风险：依赖库、求解器和交易日历版本都可能造成漂移。

### 10.10 `DeploymentGate`

- 输入：全部 OOS、可行性、成本、去重和数据泄漏审计。
- 输出：允许部署、仅研究、拒绝。
- 参数：系统固定门槛；策略不可降低硬门槛。
- 当前状态：已有策略 acceptance gate，但算子扩展后需增加检查项。
- 风险：把研究期高收益当成部署许可；部署 gate 必须与研究目标分开。

## 11. 推荐的复杂策略组合示例

下面是一个“复杂但仍可审计”的目标规格。它不是当前执行器已经支持的完整策略，
而是展示算子如何连接；标记为 `[现有]` 的部分可以直接映射当前代码，`[扩展]`
的部分需要先实现算子。

```text
BaseUniverse[csi_all] [现有输入约定]
  → IndexMembershipFilter[沪深300 + 中证500，按生效日 PIT] [扩展]
  → StatusExclusionFilter[剔除 ST、停牌、退市整理] [扩展]
  → ListingAgeFilter[min_listing_days=120] [扩展]
  → LiquidityFilter[20日平均成交额 >= universe 横截面 30 分位] [扩展]
  → PriceLimitTradabilityFilter[不可买入股票不进候选，不自动清仓] [扩展]
  → FactorGroupBlend [扩展]
      价值组：book_to_market、earnings_yield，组内等权
      质量组：ROE、cash_flow_to_assets，组内等权
      风险组：low_volatility、downside_volatility，方向统一后组内等权
      价量组：reversal、liquidity，组内等权
      组间权重：价值 30%、质量 30%、风险 25%、价量 15%（事前冻结）
  → IndustryNeutralize[申万一级，最小行业样本 10] [扩展]
  → CrossSectionalRank[逐组 rank 后再合成] [部分现有]
  → CascadedFactorGating [扩展]
      第一层：质量组综合分 >= 40 分位
      第二层：流动性 >= 30 分位
      第三层：风险组综合分 >= 35 分位
  → TopKSelector[K=80] [现有 Top-N]
  → HoldingBuffer[旧持仓保留阈值=前 120 名，新入场阈值=前 80 名] [扩展]
  → HierarchicalWeighting [扩展]
      先把行业权重限制在基准行业权重 ± 5 个百分点
      再按综合分 rank 配置行业内个股权重
      单票上限 2.5% [现有 cap 语义]
  → ConstrainedWeightProjection[无解时保留现金并告警] [扩展]
  → DriftBandRebalance[单票偏离 1.5% 才交易，季度强制重平衡] [扩展]
  → ParticipationCap[单日成交额参与率 <= 10%] [扩展]
  → LotRounding[整手，现金残差] [扩展]
  → SignalLag[1 个交易日] [现有]
  → FixedExecutionCost[买 10 bps、卖 10 bps] [现有]
  → WalkForwardEvaluation + ABLATION + FeasibilityAudit [部分现有/扩展]
```

该例中，智能体可以声明的是“选哪些已存在因子、选择哪一种已注册算子、以及在
允许范围内给出 K、阈值和权重”等；系统必须拒绝以下内容：

1. 自定义 Python、SQL 或任意表达式代码；
2. 修改买入/卖出成本、信号滞后下限、PIT 规则、远端 worker 校验；
3. 引用未在冻结 working set 中的因子；
4. 使用未来的指数调样、财报发布日期之后才公开的数据或未来成交量；
5. 在没有降级规则时把无解的约束优化器强行改成 unconstrained 结果。

## 12. 建议的 schema 分层

不要让一个平面 JSON 同时承载所有语义。建议拆成以下层：

```text
StrategySpec
├── universe_pipeline[]       # 只产生 eligible mask
├── signal_pipeline[]         # 只产生 factor/signal panel
├── selection_pipeline[]      # 只产生 selected set
├── weighting_pipeline[]      # 只产生 target weights
├── constraint_pipeline[]     # 只投影到可行权重
├── execution_pipeline[]      # 只产生可执行订单和成交残差
├── risk_policy                # 有限状态机，不允许任意动作
└── audit_policy               # OOS、消融、可行性、去重、manifest
```

每一层只能读规定的数据类型，避免“过滤算子偷偷改权重”或“权重算子偷偷读取
未来收益”。对每个 pipeline 保存输入和输出 schema checksum，可以在远端 worker
中逐层验证，而不是只验证最终收益数字。

## 13. 四模型补充意见与质量审查

本轮使用环境变量中的 provider key，通过各自 Anthropic 兼容接口调用了指定模型；密钥
未写入文档、日志或结果。模型意见只作为设计输入，以下审查结论由本项目约束和当前
代码边界决定。

| 模型 | 调用结果 | 有价值的建议 | 审查结论 |
|---|---|---|---|
| Mimo `mimo-v2.5` | 成功返回结构化 JSON | 候选池过滤、级联筛选、行业/风格约束、权重优化、换手约束、可交易性、波动/回撤控制、OOS 审计 | 方向正确，但 `PCA`、最大化 Sharpe、滑点阈值、动态停止交易等都必须进一步限制为版本化确定性算子；已吸收为 `LiquidityFilter`、`CascadedFactorGating`、行业/风格约束、风险和 OOS 算子 |
| MiniMax `MiniMax-M3` | 成功返回最完整的结构化 JSON | PIT 指数成分、上市年龄、ST/停牌/涨跌停、行业风格中性化、缓冲区、参与率、整手、分阶段执行、manifest | 质量最高、最贴近工程落地；但其提出的 `side_aware_impact` 不能改写固定 10/10 bps，只能作为未来独立冲击模型审计情景；已大部分吸收 |
| DeepSeek `deepseek-v4-flash` | 首次响应只有 thinking，短提示重试后成功 | 中性化、复合因子、可交易过滤、行业偏离、换手收缩、因子风险优化 | 建议有用，但“因子权重可为负”“max_factor 优化目标”不符合当前 long-only、声明式和可审计边界；已吸收中性化、换手收缩和风险优化的受限版本，拒绝任意负权重/目标函数 |
| GLM `glm-5.3-flash` | HTTP 层成功但正文为空；重试时远端提前断开 | 无可审查的有效正文 | 不把空响应当作意见，不补写模型未提供的结论；本轮没有 GLM 证据 |

### 13.1 明确采纳

- PIT 的指数成分、上市年龄、ST/停牌/涨跌停和流动性过滤；
- 级联筛选和行业/风格暴露约束；
- 因子组内/组间组合、中性化和缺失值策略；
- 持仓缓冲区、漂移带、换手收缩、参与率、整手和未成交订单；
- 波动率目标、回撤状态机、压力测试和集中度监控；
- walk-forward、成本敏感性、参数扰动、算子/因子消融、可行性和数据泄漏审计；
- 版本化 manifest、参数 hash、worker/schema 版本和可复跑检查。

### 13.2 只在受限版本中采纳

- IC 加权：只能使用事前冻结窗口产生的权重，不能每期用当期结果反推；
- 协方差/风险优化：必须固定求解器、收敛条件、正则化和无解 fallback；
- 动态风险控制：只能是预先定义的有限状态机，不能让 LLM 发出任意“减仓/暂停”指令；
- 冲击成本和滑点：当前生产成本仍是买 10/卖 10 bps，冲击模型只能作为独立审计情景，不能覆盖固定成本。

### 13.3 当前不采纳

- 让模型声明成本、滑点或交易费率；
- 让模型输出可执行代码、任意数学表达式或自定义优化目标代码；
- 允许负权重、做空或通过“负因子权重”绕过 long-only 约束；
- 只凭一次历史回撤触发不可逆熔断；
- 把模型建议中的“最大化 Sharpe”直接作为在线目标；
- 使用当前成分回填历史、未来成交量或公告后才可见的字段；
- 把 OOS 结果反复用于调参后仍称为样本外证明。

## 14. 推荐实现顺序

1. **第一阶段：候选池和数据时序** — `BaseUniverse`、PIT `IndexMembershipFilter`、
   `StatusExclusionFilter`、`ListingAgeFilter`、`LiquidityFilter`、`PriceLimitTradabilityFilter`、
   `DataQualityFilter`。
2. **第二阶段：信号 DAG** — `Winsorize`、`MissingValuePolicy`、`IndustryNeutralize`、
   `FactorGroupBlend`、`FactorInteraction`，并保留逐因子贡献。
3. **第三阶段：组合约束** — `HoldingBuffer`、行业/风格约束、`CashResidualPolicy`、
   `ConstrainedWeightProjection`。
4. **第四阶段：交易可行性** — `DriftBandRebalance`、参与率、整手、分阶段执行、未成交订单。
5. **第五阶段：风险与审计** — 有限状态风险控制、walk-forward、敏感性、可行性、数据泄漏、manifest。

每阶段都应先定义 schema、失败策略和单元测试，再接入 LLM proposal；不要一次性把
全部算子暴露给智能体。首批开放给智能体的参数应控制在低维、离散、有明确金融含义
且容易做 OOS 审计的集合内。
