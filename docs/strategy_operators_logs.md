## 策略层实现事实（strategy/ + strategy worker）

改动 `rdagent/scenarios/gf_quant/strategy/` 或 `scripts/gf_quant_strategy_worker.py`（下称 worker）前先读本节。算子总目录与两端锚点见 `rdagent/scenarios/gf_quant/strategy/operators.py`；两端一致性由 `test/scenarios/gf_quant/test_strategy_worker_parity.py` 守护，改完必须复跑。

1. 信号链路两端各有一份实现：本地前端 `strategy/signal.py`（transform→winsorize→standardize→方向→rank→blend，批次 A1 起）、worker 端 `run_request`（worker:483-486 及 `_apply_transform`/`_apply_winsorize`/`_apply_standardize`）；调仓日历推导仍只有 worker 有（worker:179-191），本地仅 `remote.py:126/132` 下发 directions/rebalance_frequency。新增信号侧算子必须同时落 `signal.py` 与 worker 镜像函数，并进 `SignalSpec`/`_validate_request` 白名单。注意：端到端 parity 的数值 case 对单调信号变换无鉴别力（效果被 percentile rank 吸收），信号管线由 parity 内的「同面板直连比对」case 守护，新阶段必须同步加直连比对参数组。
2. worker 的 `_target_weights`（worker:212-239）不支持 eligible 面板，只按 NaN dropna；本地 `build_target_weights`（composition.py:94-107）支持 eligible 但请求 payload 无该字段。门控类算子按「不达标置 NaN」实现，两端天然一致。
3. 给 CompositionSpec/BacktestSpec/SignalSpec 加字段会改 canonical_payload → strategy_id 身份哈希（candidate.py:210-224，strategy_id_for 在 registry.py:169），registry 既有记录随之失配；worker 拒绝 backtest 内任何 cost 键（worker:99-100），因子数硬白名单 2–8（worker:82-83）。
4. 新增 weighting 档必须同步四处：candidate.py:25、worker:92、proposal.py:126（payload→spec 在 :173-206）、以及 composition.py:15-31 与 worker:226-235 两个执行分支；漏一处即 parity 变红。
5. worker `_score` 混合语义（worker:351-358）：任一因子当日缺失即该股整体缺失（`fill_value=0.0` 只影响中间值，valid 掩码拦输出）；扩展 FactorBlend 权重时重写这段并保持该语义。
6. worker return_profile 的日收益舍入到 10 位（worker:531-534）；ReturnProfileDedup 的相关性输入是舍入后序列，阈值敏感时注意。
7. proposal 的 LLM 词表在 proposal.py:109-144（weighting 行 :126、cost 禁令 :141-143），payload→spec 在 :173-206；worker 要求因子 ≥2 而提案引擎允许 1（proposal.py:57-58 vs worker:82），新增提案字段时两端校验必须对齐。
8. 持仓漂移会把权重顶过 weight_cap（parity 实测 cap=0.2 时某日 start-of-day 权重 0.20039，两端行为一致地超限）；DriftBand / SingleNameFloor 的判定必须基于目标权重，不得使用漂移后的 start-of-day 权重。
9. 门控（批次 A2：`GateLayer`/`GatingSpec` 挂 `StrategyCandidate.gating`，本地 `strategy/gating.py`，worker `_validate_gating`/`_apply_gating`）：不达标置 NaN、层间 AND；`min_pass` 是门控层存活下限，下游 dropna 后的最终持仓可低于 min_pass（两端一致）；SingleNameFloor 等涉及「最少持仓」的算子需显式声明与该口径的关系。门控收窄截面会放大 cap 触发频率与单名权重（cap water-filling 在门控之后）。
10. `GatingSpec` 仅在启用时进 canonical payload（candidate.py:329-331），禁用门控不改变 strategy_id，历史 registry 记录不失效；后续 spec 字段照此模式（默认关闭 → 不进 payload）。
11. worker 的 ablation contributions 走 ungated 路径（worker:571-581），与 gated 主路径不同源，对比贡献度时注意。
12. proposal 词表字段 `gating_layers` 映射为 payload 的 `gating`（proposal.py:139-144/182）；spec 字段的 prompt 词表、payload→spec、worker 白名单三方键集必须逐字符对齐（A2 样板：`candidate.py` 的 `GatingSpec.as_payload`/`GateLayer.as_payload` 键集 ↔ worker `_validate_gating` 的键集清单，用符号定位，别信行号）。两端错误形态现状不一（缺失键本地 KeyError / worker ValueError），A3 起新增校验统一用 ValueError。
13. 批次 A3（§6.2 SingleNameFloor / §7.4 ScoreTransformWeight）：Floor 以 `CompositionSpec.weight_floor` + `weight_floor_allow_cash` 表示，**在 cap 之后**执行（两端 `build_target_weights` / `_target_weights` 同位置调用 `_apply_weight_floor`，逐字镜像）；判定基于目标权重（事实 8），只作用于已持有名（weight>0），小额名升至 floor、缺口由其余名的 floor 之上超额按比例出资，出资者只被缩向 floor 不低于它；floor×K 超预算直接 ValueError（文档未定，保守解释：不把任何人压破 floor）；现金残差沿用 cap 口径（`weight_floor_allow_cash=False` 时残差变 ValueError）；floor ≤ cap 由 spec 校验保证，floor 后不会重新触顶。ScoreTransform 是 weighting 档 `score_transform`，参数 `score_transform_kind`（linear/truncated/sigmoid）+ slope + cut，变换后按比例配权：linear/sigmoid 要求变换后逐名严格为正否则 ValueError；truncated 把 ≤cut 的分截断为**零权重**（该名仍被 top_n 选中但不持仓，cap water-filling 与 floor 都不会复活它），仅当全部截断才 ValueError；linear 无截距参数故数值上等价于 proportional（保守解释已注明）。新字段仅在启用时进 payload（事实 10 模式），禁用不改 strategy_id；「四处同步」落点：candidate.py WEIGHTING_SCHEMES/SCORE_TRANSFORM_KINDS、worker `_validate_request` weighting 白名单与 composition 校验、proposal.py weighting 行 + payload→spec、composition `_scheme_weights`/worker `_target_weights` 两个执行分支。parity 内有 `_apply_weight_floor`/`_score_transform_weights` 直连比对、cap+floor 叠加端到端 case 与两端同消息的 fail-closed case。truncated 零权名不计入 `avg_holdings`（worker 用 `(weights != 0).sum`）但在 turnover 的起止权重差中显进出；A4 TurnoverShrinkage 须先定义这类名是否参与收缩。`weight_floor_allow_cash` 进 payload 但不在 LLM prompt 词表（执行细节不暴露给 LLM，有意为之）。
14. 批次 A4（§8.3 DriftBand / §8.5 TurnoverShrinkage）：两个执行层算子以 BacktestSpec 字段表示（`drift_band_name`/`drift_band_portfolio`/`drift_band_forced_days`/`turnover_shrinkage`/`turnover_max_step`，默认 None 即关闭不进 payload），两端实现在 backtest.py 与 worker `_backtest` 的**主循环内**（镜像函数 `_drift_band_triggers`/`_shrink_turnover` 逐字相同、签名同为 `(carried, target, *params)`），主循环不可再单独抽函数级 parity——改动必须两端同改并复跑端到端 parity。
15. DriftBand 判定是事实 8 的**唯一显式例外**：band 比较读 carried（漂移后 start-of-day）权重对目标权重，band 触发为严格 `>`（恰在带上不触发）；skip 的调仓彻底作废（下一目标只到下一命中调仓日，不补发）；`drift_band_forced_days` 计数含非决策日（计数 = 上次成交后已完成交易日数，最小成交间隔 = forced_days+1），强制成交优先于 band，且须至少配一条 band。parity 的 band 端到端 case 依赖 discrimination 断言（band skip 的 turnover 必须 < baseline、forced case 权重必须等于 baseline），改 band 默认值或语义先看这几条。
16. TurnoverShrinkage 在 band 判定**之后**作用于成交（soft 全向量缩放、hard clip 以含现金半 L1 为口径，两者可叠加），对 truncated 零权名不特判（随向量自然收缩）；收缩改执行不改成本公式（换手计量原样作用于 executed delta）；收缩后执行权重可低于 floor、band skip 可高于 cap（cap/floor 只判目标权重，文档未声明该相互作用，已知且两端一致）。
17. worker `_validate_request` 新增 `BACKTEST_KEYS` 白名单（未知 backtest 键 ValueError），本地 `BacktestSpec.from_payload` 保持宽松（兼容 legacy cost_bps，勿加白名单，round-trip 测试依赖）；整数型 execution 字段两端必须同语义校验（A4 缺口已修：非整数 ValueError）。
18. 批次 B1 信号 DAG（§4.5/§4.9/§4.10/§4.11）：信号管线顺序固定为 transform→winsorize→standardize（A1）→missing_value（值空间）→方向乘法→percentile rank→neutral_rank 填充（rank 空间）→interaction→blend；SignalSpec 新增 `missing_value`/`missing_max_fill_ratio`/`blend_weights`/`blend_groups`/`blend_group_weights`/`blend_within_weights`/`interaction_pairs`，全部默认关闭不进 payload（事实 10 模式）。禁用路径与 B1 之前逐位一致，parity 内有 pre-change 参考哈希回归红线 case（`test_disabled_signal_dag_matches_the_pre_change_reference`，含指标与两端权重 SHA-256）。
19. MissingValuePolicy（§4.5）：`drop_stock`=面板内任一缺失即剔除该名（文档未给阈值，保守取「任一缺失」）；`cross_section_median` 在 A1 之后、方向乘法之前按当日有效截面中位数填充（两端镜像 `apply_missing_value`/`_apply_missing_value`）；`neutral_rank` 在 rank 之后把缺失名次填 0.5（`apply_neutral_rank_fill`/`_apply_neutral_rank_fill`）；`missing_max_fill_ratio` 只允许配填充模式，超限两端同消息 ValueError「missing_value fill exceeds ...」。注意 percentile rank 对剔除 NaN 名不变，drop_stock 的端到端效果只在「被剔名彻底不可持仓」；管线中填充会救活原本被 any-missing 掩码杀掉的格子，下游（top_n、gating 存活数、cap/filling、avg_holdings）随之可见。
20. FactorBlend（§4.9）与 FactorGroupBlend（§4.10）互斥（保守解释，两端校验），统一由 worker `_score(ranks, names, signal)` 与本地 `blend_member_panels(ranks, names, spec)` 实现；固定权重恒按和归一化（文档「是否归一化」未定，保守取归一化）；组混合要求 `blend_groups` 精确划分候选因子（`blend_within_weights`/`blend_group_weights` 缺省为等权），interaction 成员以单例身份进组间层；三种模式的缺失语义都是「任一成员缺失即整格缺失」，事实 5 的默认语义保持（worker `_score` 无配置分支逐字未动）。
21. FactorInteraction（§4.11）：`interaction_pairs=[a,b,kind]`，kind∈product/min/geometric_mean（gated interaction 未实现），输入是两端最终 rank 面板（「是否先 rank」保守取 rank-first，避免 z-score 乘积放大噪声），产物是「额外 blend 成员」（乘/min/几何平均后重排百分位），不是替换混合；任一输入缺失→交互项缺失→整格缺失；上限 8 项（`MAX_INTERACTION_TERMS`）；成员名 `f"{a}*{b}"`；`blend_weights` 启用时键集必须=候选因子∪交互成员名（candidate `__post_init__` 与 worker `_validate_signal` 双侧同消息校验，`_validate_signal` 现在接收 factor_names）。
22. worker 消融贡献路径（`_score(ranks, kept)`，两参调用）仍走无 signal 的等权混合，不消费 blend/missing/interaction 配置——与事实 11 的 ungated 口径一致。
23. 等权 top-N 选择对纯分数权重变化不敏感（parity 探针实测：value 权重 0.9 的 flat blend 与等权混合端到端逐位相同；percentile rank 对剔除 NaN 名也不变）：给信号侧算子写 e2e 鉴别 case 时，blend/interaction 用 proportional weighting 或让交互项占主导权重；drop_stock 鉴别须把一个**已持有**名**部分**置 NaN（部分置 NaN 的 helper 是 `_make_symbol_missing(..., partial=True)` 默认）。

24. 批次 B2（§5.5 HoldingBuffer / §5.6 DiversitySelector）：选择层两算子以 CompositionSpec 字段表示（`holding_buffer_entry`/`holding_buffer_retain`/`holding_buffer_max_extra`/`diversity_max_correlation`，默认 None 关闭不进 payload，事实 10 模式；entry 启用时 retain 缺省折叠为 entry、max_extra 缺省 0，resolve 发生在 `__post_init__`，payload 恒写解析后的三键）。二者需要「上期执行后仍持有的名」与收益历史，落点在两端回测主循环：`run_portfolio_backtest` 与 worker `_backtest` 新增可选 `composition`+`score` 参数（仅启用时传入，调用方点：parity `_local_portfolio`、worker `run_request`），镜像函数 `composition.build_buffered_target_row` / worker `_build_buffered_target_row` 逐字对齐，parity 内有直连比对。语义（保守解释）：percentile 从顶部计（最优名 1.0、最差 1/count），阈值比较含等号；held 且在自然 top_n 内必留（entry 阈值不能驱逐它）；retain 只救掉出 top_n 的 held 名——先补 entry 阈值挡出的空位，再吃 max_extra 个额外席位；diversity 是硬约束：被贪心相关屏筛掉的名 buffer 不能救回，每位入选者（含被救回者）都过同一贪心屏（按分数序逐个检查与已入选者的相关）；相关性用决策日已实现的日收益（两端同为回测 returns 面板的 `corr(min_periods=2)`，历史不足 2 行或缺失对→不设限），相关严格 `> max_corr` 才挡（负相关放行）；文档的每行业最少/最多持仓数因两端均无行业标签数据未实现（industry_ci.parquet 在数据机 G:/base 上，strategy worker 不加载、无法核实格式）。enabled 时 `run_portfolio_backtest` 会校验 score 面板覆盖 target 日期、score 列 ⊆ returns 列；`weight_floor_allow_cash` 同样不进 LLM 词表，buffer/diversity/min_holding 三组字段进词表（proposal payload→spec 已同步）。
25. 批次 B2（§8.4 MinimumHoldingPeriod）：`BacktestSpec.min_holding_days`（默认 None；整数校验与 A4 同式：非整数/ <1 ValueError）。执行次序保守定为 target → band 判定 → shrink → min-holding clamp（锁是最后一道否决，band 的 skip/force 语义与成本公式不动）。锁语义：held（carried>0）且 `position - entry_index[name] < min_holding_days` 的名成交权重抬回 carried（镜像 `backtest._apply_min_holding`/worker `_apply_min_holding` 逐字相同）；被抬部分由其余名按 executed 权重等比缩放出资（factor 钳到 [0,1]；锁定期内未卖出的锁定名不参与缩放——同日买入的另一名会把新买入挤到 0，这是有意语义）；**资金不足时整笔放弃该日调仓：unlocked 可出资额度（未锁名 executed 之和）< 需抬回额度（含 unlocked_sum==0）→ `_apply_min_holding` 返回 None，weights 保持 carried**（与 band 内 skip 语义一致，days_since_rebalance 同样 +1；理由：部分抬回 = 锁定名被部分卖出，违背锁约束本身，且无出资方时书会膨胀——verifier 曾测得行和峰值 2.3521）；资金充足分支 executed 总量守恒，成交书行和 ≤ 1+1e-9 恒成立（e2e 权重面板有守恒断言，含 daily+mhd=5+top_n=2 复现口径与全锁定专项 case）；entry_index 在 executed 权重从 0 变正时置当日、归零时删除（再买入重新起算）；文档的「强制退出例外」无引擎内触发定义，未实现；forced_days 强制成交同样受锁约束。月频下锁通常不咬合（调仓间隔远超 N），鉴别 case 必须用 daily 调仓（parity 里改 `request["evaluation"]["rebalance_frequency"]="daily"`）。
26. 三算子与 min_pass 口径（事实 9）的关系：HoldingBuffer/DiversitySelector 只作用于评分截面的选择，门控杀掉的名（NaN 分）不可被 retain；MinimumHoldingPeriod 只作用于执行层曾持有的名，可让最终持仓暂时高于 top_n（avg_holdings 按 executed≠0 计数，两端同式）。三者都不改变 gating min_pass 的存活下限语义，最终持仓可低于 top_n/min_pass 的口径两端一致。
27. worker 消融贡献路径不传 composition/score（无选择层算子），但 `candidate["backtest"]` 原样传入，故 min_holding 在消融路径同样生效——主/消融执行假设一致**仅在未启用 HoldingBuffer/DiversitySelector 时成立**（这两算子经 composition+score 传入主路径，消融路径没有；经 `candidate["backtest"]` 生效的执行假设如 min_holding 两边一致），仅信号构成不同。上批 verifier 留的三个修复已落：`score_combination`/`factor_score_weights_supported` 按 signal 配置如实声明（blend_weights→"fixed_weight_blend_of_cross_sectional_percentile_rank"+True、blend_groups→"two_level_group_weight_blend_of_cross_sectional_percentile_rank"+True、否则 equal…+False，test_strategy_remote 有两断言）；interaction_pairs 非精确 [a,b,kind] 三元对在 worker `_interaction_pairs`、本地 `SignalSpec.__post_init__`/`from_payload`、proposal 四处以同消息 ValueError 拒绝（不再静默截断）；blend_weights 传 list 时本地（SignalSpec/from_payload/proposal）改为同消息 ValueError「blend_weights must not be empty」（原 AttributeError）。可选修复 §4.5「报告每期填充数量」未做：需要改 `_build_rank_panels`/`build_factor_rank_panels` 返回签名，波及 B1 红线管线与多个测试，记录不动。
28. 批次 C1（§6.3 IndustryWeightCap / §6.8 CashResidualPolicy）：行业 cap 以 `CompositionSpec.industry_weight_cap` + `industry_map`（symbol→industry 的显式配置输入，两端引擎均无行业数据，上层注入；不进 LLM 词表但进 payload 与 worker 校验）表示。执行次序保守定为 单名 cap → 行业 cap → floor。`_apply_industry_cap` 两端逐字镜像：每轮冻结全部超限行业的名字、组内按比例缩回 cap，释放的 excess 分给未冻结名——设了单名 cap 时按「单名 cap 剩余 headroom」比例分配（保证不把任何名顶回单名 cap 之上），否则按权重比例；再分配可能把别的行业顶过 cap，下一轮再冻结（每轮至少冻一组，必收敛），放不出去的 excess 留作现金残差。映射覆盖不到的名字共享保留组 `__no_industry__`，cap 对它同样生效。spec 校验：cap∈(0,1]、industry_map 必须配 cap、weight_floor ≤ industry_weight_cap（floor 在 industry cap 之后会破坏其约束）。CashResidualPolicy 以 `CompositionSpec.cash_residual_max` 表示：每行目标权重在 cap/floor 链之后检查 `1−sum > max+1e-9` → ValueError「cash residual exceeds cash_residual_max」（执行期失败，spec 合法）；None 即禁用、逐位走老路。文档的「残差再分配/再分配顺序」在本引擎不可实现（进一步投入必破 cap/floor），保守省略。

61. §10.9 第二次发射的比对参照物是**已记录的那份 manifest**（补记，非新增行为）：`StrategyAcceptanceService._governance_metadata` 里的 `_recorded_manifest(strategy_id)` 读 `registry.get(strategy_id).metadata["manifest"]`，把它与**本次现场事实**逐字段比对——现场事实来自 `RemoteStrategyEvaluator.manifest_facts()`，那只是把本 evaluator 构造时绑定的 snapshot / working set / artifact set / 评估窗原样抄出来，不重算也不新造。比对发生在 `process` 末尾 `registry.upsert(...)` **之前**，所以参照物是**上一次**留下的记录，不是本次刚写的那份。身份集合含 `snapshot_checksum` / `working_set_snapshot_checksum` / `artifact_set_id`，故只要两次发射看到的是不同的 fact，第二次必得 `field_mismatch:<字段>` → `not_reproducible`——实测同一个 registry 连发两次：facts 不变 → `comparison` + `reproducible`；只把 `snapshot_checksum`、`working_set_snapshot_checksum`、`artifact_set_id` 三者中任一改值 → 均为 `comparison` + `not_reproducible` + 对应的 `field_mismatch:`；只改 `factor_ids`（**不是**身份字段）→ 仍 `reproducible`。**由此得到一条测试契约**：任何会重写产物 checksum、重建 artifact set 或重算 snapshot 身份的 helper，必须让两次发射**复用同一个 request / 同一份 fact**——产物被改过之后，后续调用一律基于**同一个已改过的 request dict** 复制改字段，绝不重新构造（重新构造会带上新 checksum，第二次发射随之 `field_mismatch:` 变红，症状离病因很远）；反过来要断言「不可复现」本身时，故意改一处身份字段即可，不必真去重跑引擎。注意这条与 `write_strategy_manifest` 那条线（按 strategy_id 落盘、同名异内容 `raise ValueError`，见事实 57/58）无关，别混。

62. 换行策略决定冻结摘要的可比范围（提交后复核发现，代码与 registry 未动）：本仓库 `core.autocrlf = true`，`core.eol` 与 `core.safecrlf` 均未设，所以**字节级冻结摘要（CRC32 / SHA-256）只在同一份工作区上可比，跨克隆不可比**。实测：工作区为 CRLF 的四个承重文件入库 blob 是 LF 归一化形态，`git cat-file --filters HEAD:<path>`（等价于检出时的 smudge）能把工作区字节逐字节还原——`strategy/service.py` 工作区 32119 / `2A25564C` 对 blob 31433 / `B40F8A7D`，`strategy/manifest.py` 9177 / `1516B013` 对 8975 / `B5F03A35`，`scripts/gf_quant_strategy_worker.py` 301251 / `E158F272` 对 295108 / `E62451C0`，`test/scenarios/gf_quant/test_strategy_worker_parity.py` 357547 / `B8F251F5` 对 350080 / `D6212282`，四者的 `--filters` 输出与工作区逐字节相同。反过来，工作区为 LF 的文件 blob 就是冻结字节，**新克隆检出却会被改写成 CRLF**：`test/scenarios/gf_quant/test_strategy_manifest.py` 的 `12258` / `C75BEEB8` 就是 blob 本身，而 `--filters` 给出 `12570` / `43B11D22`（其中 312 个 CRLF），即那份冻结读数在别的克隆上作废。要从提交对象复现已验证的字节：CRLF 文件走 `git cat-file --filters HEAD:<path>`，LF 文件直接取 blob。彻底修法是给仓库根加 `.gitattributes` 固定归一化规则，**本轮不做、属未决项**；在它落地之前，报告里的字节读数一律标明是「本工作区」的。另一条本机 git 现象：它会残留一个 0 字节 `.git/index.lock`（我实测 9/16 11:24:31 与 9/19 18:29:32 各一只，两次时段内 `Get-Process` 都没有 git 进程持有、`git status` 也都 clean；复核者另实测到 git 自报 `warning: unable to unlink '.git/index.lock': Invalid argument`，我这边未见该行）。处置定式：**先核实 0 字节 + 无 git 进程持有 → 用回收站 API（`Microsoft.VisualBasic.FileIO.FileSystem::DeleteFile(..., 'SendToRecycleBin')`）移走**，移走后 `git add` / `git commit` 正常完成（本次提交 `58c2453b` 就是这么过的）。不要用 `Remove-Item`，也不要在未核实持有时直接删。
